### 新增 / Added

- 知识库（RAG）新增 agentic `rag_search` 工具（Subtask 4，按需启用）：`RagSettings` 增加 `ragSearchEnabled` 字段（默认 OFF），开启后主代理可在对话中主动调用 `rag_search({ collection, query, limit })` 对指定 collection 跑 hybrid (vector + BM25 / RRF) 查询，补足 send-time 预注入 top-5 chunks 之外的深度检索。返回结构化 `<rag-search-result>` envelope（`collection` / `query` / `count` + `<chunk source index score context>`），LLM 可直接解析引用。`limit` 默认 5、上限 20；分数为 RRF 融合值（ordering-only，不是概率）。`execute()` 内置 belt-and-braces 安全网（即便 stale session 把 tool 列进了 list，关闭开关后调用仍抛错不执行）；`lib/tools/index.ts` 在 `buildSessionToolArray` 阶段按 `ragSettings.ragSearchEnabled` 条件 push，OFF 时该工具既不在 tool list 也不在 system prompt 出现，LLM 不会幻觉调用。系统提示注入走 `{{RAG_SEARCH_TOOL_LINE}}` 与 `{{RAG_SEARCH_WORKFLOW_STEP}}` 两个占位符（`entrypoints/background/agent/prompt-composer.ts` 装配），关闭时占位符折叠为空字符串 + `collapseTripleNewlines` 后处理，使 OFF 状态 system prompt 逐字节与 Subtask 4 前相同（保住 Anthropic prompt cache）
- Knowledge (RAG): New agentic `rag_search` tool (Subtask 4, opt-in). `RagSettings` gains `ragSearchEnabled` (default OFF). When on, the main agent can call `rag_search({ collection, query, limit })` mid-conversation to run a hybrid (vector + BM25 / RRF) query against the named collection — complementing the send-time pre-injected top-5 chunks when the user asks for a specific section number, function name, or code identifier that the envelope does not cover. The tool returns a structured `<rag-search-result>` envelope (`collection` / `query` / `count` + `<chunk source index score context>`), XML-escaped for parseable downstream consumption. `limit` defaults to 5 and caps at 20; the `score` attribute is RRF-fused (ordering-only, not a probability). Belt-and-braces safety: `execute()` re-reads settings and throws if disabled, so a stale session whose tool list still includes `rag_search` cannot actually invoke it after the user toggles off; `lib/tools/index.ts` only pushes the tool into the session's array when `ragSearchEnabled` is true. When off, the tool is absent from both the tool list and the system prompt — the LLM has no way to hallucinate a call. System-prompt augmentation uses `{{RAG_SEARCH_TOOL_LINE}}` and `{{RAG_SEARCH_WORKFLOW_STEP}}` placeholders, wired through `entrypoints/background/agent/prompt-composer.ts`. When off, both resolve to `''` and `collapseTripleNewlines` collapses the resulting triple-newline runs so the prompt is byte-identical to pre-Subtask-4, preserving Anthropic prompt caching
- 新增 Worker Team 总开关（Fast / Team 模式切换）：在 Settings → Advanced → Worker team 卡片新增「启用 Worker 团队」开关，并在聊天输入框工具栏加入 ⚡Fast / 👥Team 切换芯片——两处共享同一个 storage 标识（`local:workerTeamEnabled`），通过 `useStorageItem` 的 watch 自动双向同步。默认开启（保留既有行为，向后兼容）；关闭时主代理不再暴露 `delegate_task` 工具、系统提示也不再注入 `<available-workers>` L1 块，主代理改用原生 `fs_create_file` / `fs_edit_file` / `fs_read_file` 等工具直接产出 artifact，整体产出时间从 30–60s 缩短到 3–5s。两侧 gate（tool registration + system prompt block）由同一个 flag 同步驱动，与 `rag_search` 的「tool + prompt must agree」模式一致——任一侧单独撤掉都会让 LLM 幻觉调用或反之不知何时用 worker。Per-role `workerModels` 配置不受影响（OFF 状态下保留 UI 供预先配置），`delegate_dom` 独立于本开关不受波及。In-flight：用户在半轮切换时正在跑的 worker 不会被取消（YAGNI），新状态从下一轮 `composeSystemPrompt` 调用（即下一次派发）开始生效
- New Worker Team master switch (Fast / Team mode toggle). Settings → Advanced → Worker team card gains an "Enable worker team" switch, and the chat composer toolbar gains a ⚡Fast / 👥Team chip — both share the same storage key (`local:workerTeamEnabled`) and stay in lockstep via `useStorageItem`'s watch. Defaults to ON (preserves existing behavior, fully back-compat). When OFF the main agent no longer sees `delegate_task` in its tool list and the system prompt no longer injects the `<available-workers>` L1 block; the agent writes artifacts directly via the native `fs_create_file` / `fs_edit_file` / `fs_read_file` family, dropping end-to-end artifact time from 30–60s down to 3–5s. The two-sided gate (tool registration + prompt block) is driven by the same flag, mirroring the `rag_search` "tool + prompt must agree" pattern — withdrawing one side alone would either let the LLM hallucinate a non-existent tool call or leave it unable to discover the capability. Per-role `workerModels` configuration is untouched (the four role pickers stay visible while OFF so users can preconfigure and flip the switch later); `delegate_dom` is independent of this switch. In-flight: a worker already running when the user toggles keeps running to completion (YAGNI); the new state takes effect on the next `composeSystemPrompt` call (the next dispatch).
- 知识库（RAG）新增 Contextual Retrieval（上下文检索，Subtask 3，按需启用）：在 `RagSettings` 增加 `contextualRetrievalEnabled` / `contextualLlmBaseUrl` / `contextualLlmApiKey` / `contextualLlmModel` 四个字段（默认全 OFF；端点默认复用本地 CLIProxyAPI）。开启后，索引流水线在「分块 → 嵌入」之间插入 `context-generation` 阶段，逐 chunk 调用轻量 LLM 生成 ≤ 40 词的上下文前缀，前缀会同时拼接到嵌入输入与 `metadata.context_prefix`（Subtask 2 的 `content_tsv` 表达式已通过 `COALESCE` 取该值，使 BM25 路径无需迁移即可吃到前缀）。长文档（> 40K chars）走「标题 + 大纲 + 前后 1–2 段」精简上下文，目标 ≤ 8K chars。LLM 调用失败/返回空均降级为空字符串（chunk 仍正常入库，仅丢失本次召回加成），并发 8。`contextualLlmApiKey` 作为密钥分类进备份系统（与 `embedderApiKey` 同形态），用户从备份恢复时按 merge/replace 策略一并还原
- Knowledge (RAG): Contextual Retrieval (Subtask 3, opt-in). `RagSettings` gains four new fields — `contextualRetrievalEnabled`, `contextualLlmBaseUrl`, `contextualLlmApiKey`, `contextualLlmModel` — all OFF by default, with the endpoint defaulting to the local CLIProxyAPI. When enabled, the indexer inserts a `context-generation` phase between chunking and embedding: each chunk is shipped to a cheap LLM that produces a ≤ 40-word context prefix. The prefix is prepended to the embed input **and** stored in `metadata.context_prefix`; the Subtask 2 `content_tsv` expression already picks it up via `COALESCE`, so the BM25 path gains the recall boost with no migration. Long documents (> 40K chars) use a slim envelope (title + outline + 1–2 surrounding paragraphs) capped at 8K chars. LLM failures / empty responses gracefully degrade to `''` — the chunk still indexes, it just loses the recall boost for that one chunk — at concurrency 8. `contextualLlmApiKey` is classified as a secret in the backup registry (same shape as `embedderApiKey`) and follows merge / replace strategy on restore

Switching to Hybrid with `pinMinScore > 0` surfaces an amber banner warning that the relevance scale changed (RRF) and the previous threshold may need lowering — without it the user's old cosine threshold would silently filter everything. - 主动压缩静默失败时弹 toast (Subtask 5)：80% 预检触发后若 `findCompactionCutPoint` 返回 `cut <= 0`（典型场景：单条用户消息本身就超过 `keepRecentTokens`，前面没有可摘要的历史），BG 广播一条新的 IPC `compaction_skipped`（`reason: 'cut_no_op'` + 当前 token / 上下文窗口 / 保留预算 / 消息数），sidepanel 通过新模块 `lib/agent/compaction-sidepanel-channel.ts` + `hooks/useCompactionToasts.ts` 用 Sonner 弹一条瞬时提醒「上下文过满无法自动压缩（已用 XX%）。可尝试删除大段粘贴内容或开启新会话。」让用户在撞 400 之前知情。常规路径 `cut <= 0` 继续静默——它要么成功压缩，要么最终走 `context_overflow` 卡片，重复提醒只会干扰；事件走 fire-and-forget，不写 `AgentPortState`、不触发 trace sentinel 清理

- MCP server cards now support drag-to-reorder: both Settings → MCP and the sidebar drawer render each card with a new grip handle on the left as the drag activator (only the handle receives `useSortable` pointer/keyboard listeners, so the toggle / edit / delete buttons never accidentally start a drag); press and drag the grip to reorder, drop writes to persistent storage and the change flows back through `useStorageItem`'s watch callback, order survives reload; keyboard reorder works too (Tab to grip → Space to pick up → Arrow keys to move → Space to drop / Escape to cancel), reorder does NOT bump `updatedAt` since the records themselves are unchanged
- Added a cross-context phase tracer for temporary performance diagnosis of the send→reply pipeline: new `lib/debug/trace.ts` exposes `startTrace(source, sessionId, initialT0?)`; every marker has the uniform shape `{ t0, deltaMs, ...extra, sessionId }`, sortable on `t0`+`deltaMs` to reconstruct the timeline. Because `performance.now()` has different origins across renderer ↔ SW, the renderer captures the anchor at `chat:t0` and ships it through the IPC `prompt.t0` field, then BG and hook each create their own handle with that same anchor so Δt is comparable across contexts. `initialT0 === undefined` strictly distinguishes "not passed" from "passed 0"; `mark()` strips `t0`/`deltaMs` from `extra` to prevent caller tampering. Phases covered: `ui:chat:t0` (Enter pressed) / `hook:recv_agent_start` / `hook:first_token` (user-perceived TTFB) / `bg:prompt_received` / `bg:agent_ready` / `bg:prompt_composed` / `bg:system_prompt` / `bg:compaction` / `bg:agent_dispatched` / `bg:agent_start` / `bg:first_token` (model TTFB) / `bg:token_n` (every 10 tokens) / `bg:message_end` / `bg:agent_end_pre_sync` / `bg:agent_end_post_sync` / `bg:title_gen_start` / `bg:title_gen_done`. Every teardown path (`agent_end` / `cancel()` running-idle / `destroySession` / `commitCompactionCancel` / compaction-cancelled / both liveness guards) calls `releaseTrace(sessionId)` to actively evict the per-session `pendingTraces` / `firstTokenSeen` / `tokenCounts` and prevent permanent placeholder growth. Toggled by Settings → About → Debug log; the Live log view streams markers in real time when the dialog is open
- Compaction summary now ships a structured JSON side-channel and a per-event VFS archive (Subtask 4): the LLM is asked to append a fenced JSON block (`schema_version: 1`, fields `goal` / `constraints` / `progress` / `decisions` / `next_steps` / `critical_context`) at the end of its existing Markdown summary; the parser walks fences from last to first, runs each candidate through `JSON.parse` and a strict `isStructuredSummary` schema guard (rejects wrong types, missing fields, `decisions[i]` not an object, etc.), then falls back to whole-output parsing if no fence matches. On parse success the result is attached to the `compactionSummary` message via a new optional `structured?` field (declared via module augmentation on pi-agent-core's `CompactionSummaryMessage`); on failure the field is **absent** rather than `null`, so existing `if (msg.structured)` guards work unchanged. The full LLM output (Markdown + JSON fence), the structured JSON, model identity, token counts and the compact-event timestamp are also archived as a single JSON manifest at `/workspaces/<sessionId>/compaction/<ISO>-<rand>.json` (ISO timestamp with `:` and `.` replaced by `-`, 6-char hex random suffix; collision probability within a single ms is ~2⁻²⁴). The archive write is atomic (`.tmp` + `vfs.rename`) so a session-destroy running concurrently with the archive write never leaves a half-written file. UI rendering (`<CompactionDivider />`) is unchanged; the structured JSON is invisible to the user today and is queryable by future inspection tooling. Archive failures are best-effort (`debugLog.warn` only) and never block the compaction path
- Proactive compaction silent no-op now surfaces a Sonner toast (Subtask 5): when the 80% pre-check fires but `findCompactionCutPoint` returns `cut <= 0` (typically because a single user message alone exceeds `keepRecentTokens` and there is no earlier transcript to summarize), the BG broadcasts a new IPC `compaction_skipped` (`reason: 'cut_no_op'` + current tokens / context window / keep-recent budget / messages count); the sidepanel fans this through a new `lib/agent/compaction-sidepanel-channel.ts` pub/sub bridge and `hooks/useCompactionToasts.ts` (single-mount subscriber pattern, mirroring `useRecorder.installRejectionToastsOnce`) to toast "Context too full to compact (XX% used). Try dropping a large paste or starting a new conversation." — heads-up before the next request 400s. The regular-path `cut <= 0` stays silent: that path either compacts successfully or eventually surfaces the `context_overflow` card, so an additional toast would only duplicate the same underlying signal. The event is fire-and-forget — no `AgentPortState` mutation, no trace-sentinel cleanup, no client response message

- `.html` / `.htm` files in the `/vfs` tab can now be previewed inline: the host page embeds a dedicated MV3 sandbox entrypoint (`entrypoints/html-preview.sandbox/`) which receives the document via postMessage and renders it inside an inner iframe (`sandbox="allow-scripts allow-same-origin allow-forms allow-modals"`, deliberately excluding `allow-popups` / `allow-top-navigation`; `allow-modals` enables `alert()` / `confirm()` / `prompt()`). Inline `<script>` and DOMContentLoaded handlers run because the sandbox page inherits the permissive manifest `sandbox` CSP (`'unsafe-inline'`); the extension-pages CSP cannot be widened to allow inline scripts (Chrome MV3 enforces `script-src 'self'` for `extension_pages` and refuses `'unsafe-inline'` at install time). The sandbox page's opaque origin makes `allow-same-origin` harmless — there is no privileged origin for the previewed document to escape into. Preview / View source toggle is preserved; in source mode the iframe stays mounted (just hidden) so script state survives a quick source peek. The raw-source path is replaced — `.html` no longer falls into the TEXT bucket
- 新增 `delegate_task` 工具，支持把长任务委派给 4 种固定的 worker role（`content_writer` / `frontend_coder` / `reviewer` / `researcher`）；worker 跑在隔离 sub-agent 上下文里，**通过 VFS 文件而非聊天 context 传递产物**（input_files 读、output_path 写），主代理 context 不被污染——拿到的只是一份 ≤4 KB 的结构化 handoff JSON（`status` / `output_file` / `summary` / `handoff_notes`）。可选 `expected_schema` 参数支持用 TypeBox JSON Schema 校验 worker 输出，校验失败自动单次自愈重试；可选 `skills` 参数自动注入 `~/.cebian/skills/<name>/SKILL.md`（复用 mention-resolver 的 `stripFrontmatter` + 100 KB truncate）；可选 `anti_patterns` 参数包装成 `<do-not-do>` 块 prepend 到 prompt；内置单次重试覆盖机械性失败（JSON 解析失败、schema 校验失败、worker 声明成功但 output_file 缺失）— 不需要主代理介入

- Added the `delegate_task` tool — main agent can offload long tasks to one of four fixed worker roles (`content_writer` / `frontend_coder` / `reviewer` / `researcher`). Workers run in isolated sub-agent context and **communicate via VFS files** (read input_files, write output_path) instead of polluting the main agent's context; the main agent only receives a ≤4 KB structured handoff JSON (`status` / `output_file` / `summary` / `handoff_notes`). Optional `expected_schema` parameter validates worker output against a TypeBox JSON Schema with automatic single-pass self-healing retry; optional `skills` parameter auto-injects `~/.cebian/skills/<name>/SKILL.md` (reuses mention-resolver's `stripFrontmatter` + 100 KB truncate); optional `anti_patterns` is wrapped into a `<do-not-do>` block prepended to the prompt; the built-in single-pass retry covers mechanical failures (JSON parse error, schema validation error, worker-declared success with missing output file) with no main-agent intervention

No runtime timeout behavior changes in this subtask; only the documentation is reconciled — a 22-line drift-fix docstring is added above the constants in `lib/agent/worker-roles.ts:287-289`, the `resolvePhaseTimeout` docstring gains a paragraph explaining the emit-phase trade-off (referencing this CHANGELOG entry), `worker-roles.test.ts` gains 2 pinning tests (`WORKER_TTFT_MS === 120_000`, `WORKER_IDLE_MS === 180_000`) so changing the literals will fail CI until CHANGELOG + plan + docstring are updated in lockstep, and 7 hardcoded `'20000ms'` / `'120000ms'` / `'45000ms'` ms-string literals in `worker-runner.test.ts` are switched to `${WORKER_IDLE_MS}` / `${WORKER_TIMEOUT_MS}` / `${WORKER_TTFT_MS}` template literals — runner error messages now self-update against the constants, but the runtime values they render to are unchanged
